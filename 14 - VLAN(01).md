# VLAN(01)

- Virtual Local Area Network


## What is a LAN

- A LAN is a single broadcast domain
  - including all devices in that broadcast domain
- A broadcast domain is a group of devices which will receive a broadcast frame
  - (destination MAC FF:FF:FF:FF:FF:FF)
  - sent by any one of the members

- routers do not forward broadcast frames
- but a router to router(point to point connection)
  - is also a broadcast domain

- switch is only aware up to layer 2

- if all devices are connected to a switch
  - when there is a broadcast, it will send it to all interfaces connected to the switch
  - lots of unnecessary broadcast traffic can reduce network performance
    - this is also a security issue
  - Security - limit who has access to what
    - with one LAN, every PC is connected
    - this makes all security policies useless


## using subnets

- split each department to its own subnet
  - engineering
  - hr
  - sales
- this means each subnet now has to have a connection to the router
- if engineering wants to send a message to sales:
  - Src. IP: eng host
  - Dst. IP: sales host
  - Dst. MAC: router MAC
  - Src. MAC: eng. MAC
  - so the message flows from the switch to router to the other network
- however a broadcast meant for all eng. department from a eng. host is still sent to all devices linked on the switch(all departments get it, the sales, hr departments and the router). it is still a security issue
  - Src. IP: eng host
  - Dst. IP: eng. broadcast host
  - Dst. MAC: FFFF:FFFF:FFFF
  - Src. MAC: eng. MAC
- though they are separated by subnets(layer 3), you want to separate at layer 2
- you can give each department a switch but equipment is expensive


## using VLAN

- they are configured on switches on a per-interface basis
  - logically separate end hosts at Layer 2
- switches don't forward traffic directly between hosts in different VLANs
- give each department its own VLAN
  - eng. - VLAN10
  - hr - VLAN20
  - sales - VLAN30
- set the separation on the interfaces of the switch
- switch will not forward traffic between VLANs
  - including broadcast/unknown unicast traffic
- if there is a packet meant to be in the same VLAN, the switch handles it
  - if it is meant for another VLAN, the router handles the forwarding
- if traffic arrives in a particular VLAN interface, it must exit through that same VLAN interface
  - eg VLAN 10 traffic only flows in VLAN 10, until the router where it switches to the intended VLAN
  - traffic is never forwarded from VLAN 10 to VLAN20 


## VLAN configuration

- show vlan brief
  - show each VLAN and what interfaces are connected to it
  - all interfaces are in VLAN1 by default
- VLAN1, 1002 - 1005 exist by default
  - they cannot be deleted

- interface range g1/0 - 3
  - select the range of interfaces g1/0 - g1/3 and configure them at once
- switchport mode access
  - set the interface as an access port
  - an access port is a switchport that belongs to a single VLAN, and usually connects to end hosts like PCs
    - gives end hosts access to the network
    - as opposed to a trunk port -> a switchport which carries multiple VLANs
    - a port usually enters access port by default but just set it to make sure
- switchport access vlan 10
  - assign the VLAN to the port
  - it creates a new VLAN 10


### general command structure

- interface range <interface range>
  - g1/0 - 3
  - g2/0 - 3
  - g3/0 - 3
- switchmode mode access
  - change the mode of the ports to access
- switchport access vlan <number>
  - 10 for vlan 10
  - 20 for vlan 20
  - 30 for vlan 30


### change vlan default name

- enter config mode
  - SW1(config)# -> this should be on the terminal
- vlan 10
  - configure vlan 10
  - this also creates a VLAN
- name <vlan-name>
  - set the name of vlan 10
- vlan 20
  - configure vlan 20
- name <vlan-name>
  - set the name you want for vlan 20
- and so on...


### after this setting

- if you ping 255.255.255.255 in any VLAN
  - it will only reach the interfaces in that VLAN and the router that has connected to that VLAN


### Why have VLANs

- reduce congestion on the network
- improve security for traffic
  - stop devices from receiving packets not intended for them
